# 설계

[전체 목차](../index.md)

클래스·모듈·시스템의 책임을 나누고 관계를 정하는 방법을 다룬다. 디자인 패턴은 해결할 문제, 적용 조건과 비용을 중심으로 정리한다. 특정 언어로 예시를 작성해도 문서의 중심은 구조와 선택 이유에 둔다.

상태: 세부 규칙 미작성. 아래 항목은 작성 범위이며 채택된 설계 규칙이 아니다.

## 정리할 순서

1. 책임 분리와 인터페이스 경계
2. 모듈·계층 구조와 의존성 방향
3. 디자인 패턴의 적용 조건과 대안
4. 시스템 사이의 상호작용과 데이터 흐름

## 다른 분류와의 경계

- “렌더러가 게임 로직에 의존하지 않는다”처럼 역할과 관계를 정하는 내용은 설계에 둔다.
- 폴더 배치와 라이브러리 타깃 구성은 [프로젝트 구성·빌드](../build/index.md)에 둔다.
- RAII와 스마트 포인터의 사용·전달 방법은 [C++ 소유권·수명](../coding/cpp/ownership.md)에 둔다.
- 특정 프로젝트에서 선택한 구조와 예외는 [프로젝트별 규칙](../projects/index.md)에 둔다.

세부 문서는 주제가 정리되면 이 목차에 추가한다.
