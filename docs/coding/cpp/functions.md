# C++ 함수 매개변수·반환 규칙

[C++ 목차](index.md)

상태: 채택 · 적용 범위: 일반 함수의 입력·입출력·결과 전달 · 예제: C++11 이상, structured binding·`[[nodiscard]]`는 C++17 이상

호출부에서 어떤 데이터를 읽고, 무엇을 변경하고, 어떤 결과를 만드는지 드러나도록 인터페이스를 작성한다. 스마트 포인터 전달은 [확정된 소유권 규칙](ownership.md#전달할-때-소유-의도를-표현한다)을 우선한다.

## 기본 선택

| 목적 | 기본 방식 | 강도 |
| --- | --- | --- |
| 복사 비용이 작은 입력 | `T` 값 전달 | 권장 |
| 복사 비용이 큰 객체를 읽기만 함 | `const T&` | 권장 |
| 기존 객체를 읽고 수정 | `T&` | 권장 |
| 부재가 유효한 비소유 입력 | `const T*` 또는 `T*` | 권장 |
| 새 결과 하나 생성 | `T` 값 반환 | 권장 |
| 의미상 묶인 결과 여러 개 | 이름 있는 구조체 반환 | 권장 |
| 호출자 버퍼 재사용·외부 API | 계약을 명시한 출력 인자 허용 | 선택 |

## 입력과 입출력

`int`, `bool`, 열거형처럼 복사 비용이 작은 타입은 값으로 받는다. 문자열·컨테이너처럼 복사할 데이터가 많은 객체를 잠시 읽을 때는 `const T&`를 고려한다. 바이트 크기 하나로 모든 타입의 전달 방식을 결정하지 않는다.

```cpp
#include <string>

bool HasPrefix(
	const std::string& text,
	char prefix)
{
	return !text.empty() && text.front() == prefix;
}

void AddBonus(
	int& damage,
	int bonusDamage)
{
	damage += bonusDamage;
}
```

`T&`는 호출자의 기존 객체를 수정할 수 있다는 의미로 사용한다. 참조가 있다고 항상 출력 전용이라고 해석하지 않는다. 부재를 허용해야 할 때는 포인터와 null의 의미를 명시하며, 수명 조건은 [소유권·수명 규칙](ownership.md)을 따른다.

**필수:** 입력 참조를 함수 호출 이후까지 저장하려면 별도의 수명 계약이 있어야 한다. 문자열·컨테이너를 자체적으로 보관할 함수는 잠깐 읽는 함수와 구분한다. 복사·이동 가능한 값을 항상 보관한다면 값 전달 후 이동 저장을 기본안으로 사용할 수 있다.

```cpp
#include <string>
#include <utility>

class Player
{
public:
	void SetName(std::string name)
	{
		mName = std::move(name);
	}

private:
	std::string mName;
};
```

조건부 저장, 버퍼 재사용, 비용이 큰 타입은 실제 호출 패턴에 따라 별도로 검토한다. 단순 입력에 관성적으로 `T&&`를 사용하지 않는다. 전달 템플릿의 `T&&`·`std::forward`는 별도 주제로 둔다.

## 반환값으로 결과를 표현한다

새로 만든 결과는 값으로 반환한다. 큰 객체라는 이유만으로 출력 참조로 바꾸지 않는다. 반환 비용은 복사 생략·이동과 호출 패턴을 함께 고려한다.

```cpp
#include <vector>

std::vector<int> CreateScores(int count)
{
	std::vector<int> scores(count, 0);
	return scores;
}
```

이 예제는 `count >= 0`을 전제로 한다. 일반 지역 결과는 `return result;`로 반환하고 `return std::move(result);`를 기계적으로 추가하지 않는다. 값 반환 타입에 최상위 `const`를 붙이지 않는다. 참조로 반환하는 `const T&`와는 다른 규칙이다.

관련된 결과 여러 개는 필드 이름이 의미를 설명하는 구조체로 반환한다.

```cpp
struct Size
{
	int width;
	int height;
};

Size GetDefaultSize()
{
	return {1280, 720};
}
```

단순히 결과 개수가 둘이라는 이유로 항상 `std::pair`를 사용하지 않는다. 이미 표준 API가 정한 반환형이나 범용 템플릿은 예외로 둔다.

### 구조체와 pair·tuple의 선택

상태: 채택 · 적용 범위: 복합 결과의 반환형 선택 · 개정일: 2026-10-09

**권장:** 복합 결과는 이름 있는 구조체로 반환한다. **선택:** 간단한 임시 결과나 범용 코드에서 각 요소의 의미와 순서가 명확하면 `std::pair`·`std::tuple`을 사용할 수 있다. 요소의 크기·개수나 함수의 길이만으로 선택하지 않는다.

| 반환 방식 | 사용하는 경우 | 강도·예외 |
| --- | --- | --- |
| 이름 있는 구조체 | 결과들이 하나의 개념을 이루거나 필드 이름으로 의미를 설명해야 하는 경우 | 권장. 크기·범위·파싱 결과 등 |
| `std::pair` | 두 독립적인 값을 간단히 묶으며 각 값의 의미와 순서가 명확한 경우 | 선택. 간단한 임시 결과·범용 조합 |
| `std::tuple` | 여러 독립적인 값을 임시로 묶거나 범용·가변 템플릿에서 결과를 조합하는 경우 | 선택. 별도 개념을 나타내는 결과는 구조체 우선 |
| 표준·외부 API의 반환형 | 해당 API가 반환형을 지정한 경우 | 해당 계약 우선. 이름만 바꾸기 위한 래퍼는 필수가 아님 |

`std::tuple<int, int>`나 그 별칭만으로는 각 값의 역할이 드러나지 않는다. `width`와 `height`는 작은 정수 두 개여도 크기라는 개념을 이루므로 위 `Size`처럼 구조체로 표현한다. 결과를 전달·보관하거나 여러 호출부에서 사용한다면 `size.width`처럼 필드 이름을 읽을 수 있는 구조체의 실익이 크다.

`std::tuple`은 C++11부터, structured binding은 C++17부터 사용할 수 있다. 구조체도 structured binding으로 분해할 수 있으므로 그 문법을 쓰기 위해 반환형을 tuple로 바꿀 필요는 없다.

```cpp
const auto size = GetDefaultSize();
const int width = size.width;

// C++17: Size 구조체도 분해할 수 있다.
const auto [defaultWidth, defaultHeight] = GetDefaultSize();
```

분해한 지역 이름은 반환형의 필드 계약을 대신하지 않는다. structured binding은 순서에 의존하므로 같은 타입의 필드 순서를 바꾸면 의미가 바뀔 수 있다. 이름으로 접근할 실익이 있는 호출부는 필드 접근을 유지한다. 성공 여부와 데이터·오류를 함께 반환할 때의 계약은 [결과 없음과 실패](#결과-없음과-실패)를 따른다.

구조체와 tuple 중 하나가 항상 더 빠르다고 전제하지 않는다. 반환 비용은 실제 타입·복사/이동·컴파일러·호출 패턴에 따라 확인하며, 여기서의 기본 선택은 의미와 가독성에 따른다.

## 출력 인자를 허용하는 경우

외부 API의 지정된 시그니처, 호출자가 마련한 버퍼의 재사용, 측정으로 확인된 비용 절감이 필요한 경우 출력 인자를 허용한다. 새 객체 하나를 반환할 수 있는 일반 함수의 기본형으로 삼지는 않는다.

**필수:** 입력과 출력이 섞이면 무엇을 읽고 무엇을 쓰는지 설명한다. 실패 시 출력 유지·초기화·부분 변경 중 어떤 동작인지 명시하고 구현과 일치시킨다.

```cpp
#include <string>

/// @brief 경로에 해당하는 이름을 읽어 output에 기록한다.
/// @return 성공 시 true. 실패 시 false이며 output은 변경하지 않는다.
bool TryReadName(
	const std::string& path,
	std::string& output);
```

위 예제는 출력 계약의 선언 예시다. 실제 파일 읽기 구현은 포함하지 않는다. 출력 인자는 입력 인자 뒤에 두는 것을 권장하되 외부 API의 순서는 유지한다.

## 결과 없음과 실패

- 반환할 데이터가 없는 명령은 `void`, 참·거짓 질의나 성공 여부만 필요한 연산은 `bool`을 사용할 수 있다.
- 데이터가 없을 수 있는 결과에는 C++17 이상에서 `std::optional<T>`를 고려한다. 오류 원인까지 담는 형식은 아니다.
- 오류 원인이 필요한 연산은 결과 타입·오류 코드·예외 정책을 별도로 정한다. `std::expected`를 사용한다면 C++23 및 도구 지원을 확인한다.
- `0`, `-1`, 빈 문자열을 보편적인 실패값으로 삼지 않는다. 정상 결과와 구분되는지 먼저 확인한다.

이 절은 반환형 선택의 경계만 다룬다. 프로젝트 전체의 예외 허용 범위나 오류 처리 방식은 아직 확정하지 않는다.

## 반환값 무시와 nodiscard

**권장(기존 채택 기준):** 반환값을 무시하면 잘못된 사용이나 중요한 누락이 되는 API에 C++17 이상에서 `[[nodiscard]]`를 붙인다. 판단 질문은 **“호출자가 결과를 버려도 이 API를 올바르게 사용했다고 볼 수 있는가?”**다. 반환형이 `bool`이거나 Getter라는 이유로 일괄 적용하지 않는다.

실패 후 진행 여부, 종료 요청·종료 코드, 소비한 데이터, 새로 계산한 값처럼 반환값이 호출 목적과 후속 동작의 전제인지 확인한다. 일반 Getter는 결과를 버렸을 때 생기는 문제와 경고의 실익을 개별 판단한다. 내부에서 실패를 기록하더라도 호출자가 후속 작업을 중단해야 한다면 결과 확인은 여전히 필요하다.

`[[nodiscard]]`는 반환값을 버리는 호출에 경고를 유도한다. 결과를 변수에 넣기만 해도 경고 대상에서 벗어날 수 있으므로 실제 검사·사용까지 보장하지 않는다. 함수·타입 적용 범위와 버전별 표기는 [attribute 문서](attributes.md#nodiscard의-적용-범위와-진단)를 따른다.

### 의도적인 반환값 무시

상태: 채택 · 적용 범위: 결과를 사용하지 않아도 계약이 성립하는 호출부 · 개정일: 2026-10-09

- **필수:** 우선 결과를 검사·사용·상위 호출자에게 전달해야 하는지 확인한다. 실패 후 진행 여부를 정해야 하는 호출에 경고 제거만을 위한 캐스트를 넣지 않는다.
- **권장:** 반환값을 의도적으로 무시함을 표시할 때는 `(void)Function();`을 기본 표기로 사용한다. 결과를 버리는 이유가 검토상 중요한 호출에도 이 표기를 사용한다.
- **선택:** 결과 무시가 자연스럽고 계약상 문제가 없는 일반 호출은 `Function();`만 작성할 수 있다. 모든 비-void 호출에 별도 표기를 요구하지 않는다.
- **필수:** `[[nodiscard]]` 결과를 무시하는 허용된 예외는 명시적으로 표시한다. 결과 무시가 허용되는지를 먼저 판단하며, attribute가 없는 함수도 결과 확인이 필요한 계약이면 검사한다.
- **필수:** 실패 결과를 버리는 예외에는 실패를 어디서 보고하는지와 이후 어떻게 진행하는지 남긴다. 주변 계약에서 분명하면 같은 설명을 호출마다 반복할 필요는 없다.
- **선택:** 프로젝트의 기존 스타일이나 도구 정책에 따라 `static_cast<void>(Function());`·`std::ignore = Function();`도 사용할 수 있다. `std::ignore`는 `<tuple>`을 직접 포함하고 지원 라이브러리·분석 도구의 동작을 확인한다. 같은 프로젝트에서는 특별한 이유 없이 여러 표기를 섞지 않는 것을 권장한다. `(void)`를 수치·포인터의 C 스타일 캐스트 규칙과 구분한다.

```cpp
// 종료 정리에서 완료를 시도한다. 실패는 함수 내부에서 보고하고 정리를 계속한다.
// 이 경로의 결과 폐기는 GPU 완료를 보장하지 않는다.
(void)WaitForGpu();
```

위 코드는 예외 표기의 예시다. 소멸자라는 이유만으로 실패 무시가 안전해지는 것은 아니다. 자원 정리의 안전 조건은 프로젝트 계약에서 따로 확인한다. 정상 실행·자원 재사용 경로에서 완료 여부가 전제라면 결과를 검사한다.

표준의 진단 권고는 명시적인 void 캐스트를 제외한다. 캐스트는 호출을 생략하거나 부작용·예외를 없애지 않는다. 경고를 피하기 위해 사용하지 않을 변수에 결과를 저장하거나 `[[maybe_unused]]`를 붙이는 방법은 기본안으로 삼지 않는다. `[[maybe_unused]]`는 엔터티의 미사용 의도를 나타내는 별도 attribute다.

`(void)` 기본 표기는 [RnimanEngine 확인 사례](../../projects/rniman-engine.md#반환값과-attribute-확인)와 사용자 선택에 따른 개인 규칙이다. Microsoft C4834 문서는 의도적 무시에 `std::ignore` 대입을 우선 제안한다. 이 컨벤션은 기존 호출부 표기를 유지하고 `<tuple>` 의존성을 추가하지 않는 이유로 `(void)`를 권장 기본으로 채택하며, 프로젝트의 스타일·도구 정책에 따른 다른 표기도 허용한다. MSVC 코드 분석 C26457 등 추가 진단은 별도로 확인하며 진단 설정은 여기서 변경하지 않는다.

## 관련 규칙과 예외

- 함수명은 [명명 규칙](naming.md), 여러 줄 매개변수와 닫는 괄호 배치는 [포맷 규칙](formatting.md)을 따른다.
- 매개변수의 `const` 위치와 지역 변수 적용 기준은 [const 사용 규칙](const.md)에 둔다.
- 포인터·참조·뷰 반환의 유효 기간과 비동기 저장은 [소유권·수명 규칙](ownership.md)에 둔다.
- 매개변수가 많거나 비슷한 `bool`·정수 인자가 반복되면 이름 있는 옵션 타입이나 열거형을 검토한다. 단순히 인자 개수를 줄이기 위한 무관한 값의 묶음은 피한다.
- 오버라이드·콜백·C ABI 등 외부에서 지정한 함수 형태는 해당 계약을 우선한다.

## 근거와 출처

[기존 자료](../../../ref/CodingConvention.md)의 읽기 전용 입력·반환값 원칙과 기존 COM 출력 인자 사례를 참고했다. 읽기 전용 입력을 무조건 `const T&`로 받는 해석은 피하고 비용과 의도로 구분한다. 외부 API의 출력 방식은 일반 함수 전체의 기본값으로 확대하지 않는다.

C++ Core Guidelines의 입력·입출력 구분과 값·구조체 반환 권고를 참고했다. 값 전달 후 저장, 출력 인자 배치와 실패 계약의 구체화는 이 저장소의 선택이다.

- [F.16 — 입력 매개변수](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#Rf-in)
- [F.17 — 입출력 매개변수](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#Rf-inout)
- [F.20 — 반환값 우선](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#Rf-out)
- [F.21 — 여러 결과의 구조체 반환](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#Rf-out-multi)

출처 확인일: 2026-09-12.

추가 확인일: **2026-10-09**. 기존 `ref/`의 반환값·오류 처리 사례는 참고 근거로 유지하며, 그 예외 정책을 공통 규칙으로 확대하지 않는다. 기존 구조체 반환·`[[nodiscard]]` 권장의 강도는 유지한다. 사용자 선택으로 구조체·pair·tuple의 사용 범위와 의도적 결과 무시의 조건·표기를 구체화해 채택했다.

- [C++ Core Guidelines F.21 — 구조체와 tuple-like 반환](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#Rf-out-multi): 문서 표기 2026-06-14, 현대 C++20 중심. 이름 있는 구조체 우선과 독립적인 값·가변 템플릿의 pair·tuple 사용을 참고했다. 간단한 임시 결과에서 의미·순서가 명확할 때 허용하는 범위는 사용자가 선택한 개인 규칙이다. 요소 크기나 함수 길이를 기준으로 삼지 않아 기존 구조체 우선 원칙을 유지한다.
- [C++ 작업 초안 — dcl.attr.nodiscard](https://eel.is/c++draft/dcl.attr.nodiscard): 경고 권고와 명시적인 void 변환 예외. 갱신되는 작업 초안이며 적용 버전은 C++17 기본형·C++20 이유 문자열로 구분한다.
- [Microsoft C4834 — Remarks·Example](https://learn.microsoft.com/en-us/cpp/error-messages/compiler-warnings/c4834?view=msvc-170#remarks): Visual Studio 문서 뷰 `msvc-170`. 경고·의도적 결과 무시와 `std::ignore` 권고, C26457 가능성을 확인했다.

채택일: 2026-09-12. 명시된 적용 범위 안에서 채택하며, 후속 정리 대상은 제외한다.

## 미결정 사항과 변경 기록

프로젝트 오류 처리와 진단 설정은 별도 결정하며 보류·폐기로 확정한 항목은 없다.

- 2026-10-09: 사용자 선택으로 구조체·pair·tuple의 선택 기준과 의도적 결과 무시의 `(void)` 권장 기본·표기 생략·대체 표기 허용 범위를 채택했다. 기존 nodiscard 기준과 진단의 한계를 설명하고 attribute 초안으로 연결했다. 오류 처리·진단 설정은 프로젝트별 결정으로 유지한다.
