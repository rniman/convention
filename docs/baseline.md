## 적용 방식

- 각 문서의 `필수`, `권장`, `선택` 강도를 그대로 유지한다. 채택이 모든 권장을 필수로 바꾸는 것은 아니다.
- C++ 규칙은 신규 개인 C++ 코드에, Git 규칙은 개인 프로젝트의 새 커밋 메시지와 작업 브랜치 이름에 적용한다. 기존 프로젝트는 명시적 프로젝트 합의를 우선하고 변경하는 범위부터 적용한다.
- 규칙이 여러 주제에 걸치면 상세 정의가 있는 문서를 따른다. 스마트 포인터 전달은 소유권 문서, const 여부는 const 문서, 이름은 명명 문서가 기준이다.
- `ref/`는 과거 자료와 비교 근거다. 현재 규칙과 다르면 이 목록의 기준 문서를 따른다. 외부 가이드도 참고 근거이며 개인 규칙을 자동으로 대체하지 않는다.
- 예제의 최소 언어 버전과 프로젝트 표준 버전은 구분한다. C++11·14 기본 예제와 C++17·20·23 조건부 기능을 프로젝트 지원 범위에 맞게 사용한다.
- 문서의 후속·미결정 사항은 채택된 규칙으로 확정한 것으로 해석하지 않는다. 언급되지 않은 사항은 프로젝트에서 일관된 방식을 선택하고 필요 시 다음 개정에 추가한다.

## 다음 개정 범위

| 영역 | 남은 내용 |
| --- | --- |
| 명명 | 파일·네임스페이스·약어·매크로, 일반 구조체 정적 변수 |
| 포맷 | switch·짧은 람다·복잡한 템플릿 |
| 언어·설계 | 오류 처리의 통일 정책, mutable, 전달 템플릿 |
| 빌드·도구 | 표준 버전·컴파일러, PCH·모듈, 자동 포맷·편집기 설정 |
| 프로젝트별 규칙 | COM·DX12·GPU 자원·ECS·메모리 풀 |
| Git·협업 | 병합·리뷰·브랜치 수명, 자동 생성 메시지·릴리스·검증 도구 |
| 다른 분류 | C, 테스트·품질, 일반 문서화 |

미작성 분류는 탐색 구조만 유지한다. 위 후속 항목과 도구 설정은 이번 채택 범위에 포함하지 않는다.

## 변경 기록

- 2026-09-12: 사용자 요청으로 Git 커밋 메시지·브랜치 명명 규칙을 추가 채택하여 적용 범위를 총 10개 문서로 확장했다. 본문 문단 허용과 호환성 변경의 `!`·footer 병용도 포함했다.
- 2026-09-12: 작성된 8개 문서를 개인 기준으로 채택하고 혼재된 초안 상태를 정리했다.
- 사용자 선택인 탭 표시 4칸, UTF-8(BOM 없음)·LF, 마지막 인자 뒤 닫는 괄호, 선택적 지역 const, `///` API 주석과 스마트 포인터 전달 규칙을 유지했다.
- 실제 폴더 이름에 맞춰 과거 자료 링크를 `ref/`로 통일했다.
- 2026-09-12 검토: 함수 괄호 배치에 생성자 초기화 목록·후행 지정자를 반영하고, 직접 include와 전방 선언의 적용 조건을 일치시켰다. 축소 변환 진단과 실행 중 범위 검사의 차이, 빌린 주소의 유효 조건을 명확히 했다.
- 같은 검토에서 정상값과 부재를 혼동하던 소유권 예제를 수정하고, 고정 상수와 실행 중 설정값의 명명을 구분했다. 중복 상태 표기와 검증 절의 규칙 반복을 줄였다. 기존 채택 스타일과 규칙 강도는 유지했다.

문서 경로는 다음 개정에도 유지한다. 규칙을 변경하면 해당 문서와 이 기록에 변경 범위와 이유를 남긴다. 이 페이지는 문서 기준이며 Git 태그·커밋·배포를 의미하지 않는다.
