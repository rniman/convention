채택 규칙은 포맷·명명·주석, 초기화·const, 헤더·함수·소유권 순으로 읽는다. 자료형 선택과 타입 변환 초안의 위치는 [C++ 목차](coding/cpp/index.md)를 따르며, 위 채택 범위와 구분해 검토한다.

## 적용 방식

- 각 문서의 `필수`, `권장`, `선택` 강도를 그대로 유지한다. 채택이 모든 권장을 필수로 바꾸는 것은 아니다.
- C++ 규칙은 신규 개인 C++ 코드에, Git 규칙은 개인 프로젝트의 새 커밋 메시지와 작업 브랜치 이름에 적용한다. 공통 기준은 위키의 채택 규칙이며, 기존 프로젝트도 변경하는 범위부터 맞춘다. 프로젝트 제약으로 달라지는 부분은 아래 절차에 따라 예외로 기록한다.
- 규칙이 여러 주제에 걸치면 상세 정의가 있는 문서를 따른다. 스마트 포인터 전달은 소유권 문서, const 여부는 const 문서, 이름은 명명 문서가 기준이다.
- `ref/`는 과거 자료와 비교 근거다. 현재 규칙과 다르면 이 목록의 기준 문서를 따른다. 외부 가이드도 참고 근거이며 개인 규칙을 자동으로 대체하지 않는다.
- 예제의 최소 언어 버전과 프로젝트 표준 버전은 구분한다. C++11·14 기본 예제와 C++17·20·23 조건부 기능을 프로젝트 지원 범위에 맞게 사용한다.
- 문서의 후속·미결정 사항은 채택된 규칙으로 확정한 것으로 해석하지 않는다. 미지정 규칙은 아래 절차에 따라 프로젝트에서 구체화하고 위키에 반영한다.

## 위키와 프로젝트의 상호 반영

적용 범위는 이 위키를 사용하는 개인 프로젝트다. **공통 컨벤션의 기준은 항상 위키의 채택 규칙**으로 둔다. 프로젝트에서 발견한 요구와 실제 적용 결과로 위키를 갱신하되, 프로젝트의 임시 선택과 공통 채택을 구분한다. 이 절차는 사용자가 선택한 운영 기준이다.

1. **위키 확인 — 필수.** 프로젝트 작업 전에 관련 문서의 현재 채택 상태와 적용 범위를 확인한다. 초안·보류·폐기·미결정 내용을 채택 규칙처럼 적용하지 않는다. 접근할 수 없으면 확인하지 못한 범위와 임시로 참고한 자료를 기록한다.
2. **미지정 규칙 구체화 — 필수.** 실제 구현에 필요한 선택을 프로젝트에서 정하고 적용 범위·이유·예외·필요한 예시를 기록한다. 사용자 선택이 없는 임시 결정은 시험 적용으로 표시한다. 기존 코드에서 반복된다는 사실만으로 공통 규칙을 자동 채택하지 않는다.
3. **위키 반영 — 필수.** 여러 프로젝트에 적용할 내용은 해당 공통 문서에, 특정 엔진·플랫폼에 한정된 컨벤션은 `projects/`의 해당 문서에 반영한다. 명확한 사용자 선택이나 기존 채택 근거가 있으면 그 범위에서 채택하고, 제안 단계이면 초안으로 남긴다. 미결정·보류·폐기도 구분하며 해당 문서와 이 페이지의 변경 기록을 갱신한다.
4. **프로젝트 반영 상태 기록 — 필수.** 프로젝트에는 위키 링크와 실제 적용 범위, 시험 적용·예외·미반영 사항을 남긴다. 공통 규칙 전문은 복제하지 않는다. 위키 개정으로 영향받는 코드와 요청 범위의 도구 설정을 확인하고 관련 작업 범위부터 맞춘다. 즉시 적용하기 어려우면 대상·이유·후속 반영 조건을 기록한다.
5. **결과를 다시 위키에 반영 — 권장.** 시험 적용에서 드러난 제약이나 예외를 관련 규칙에 반영한다. 임시 선택을 유지·수정·폐기한 이유를 남겨 다음 프로젝트에서도 판단 근거를 확인할 수 있게 한다.

### 기록 위치와 예외

공통 규칙의 상세 정의는 위키의 주제별 문서 한 곳에 둔다. **위키 안에서 특정 프로젝트의 핵심 요약·전용 규칙·제약·적용 상태는 `docs/projects/`에만 기록한다.** 상세 환경·설계·실행 절차·검증 기록은 프로젝트 저장소로 연결하며 위키에 복제하지 않는다. 공통 문서는 일반화한 규칙과 필요한 근거 링크만 유지하며, README·목차·사이트 메뉴에서는 프로젝트 문서로 연결한다. 프로젝트별 컨벤션과 공통 기준의 예외는 위키의 프로젝트별 문서에서 관리하고, 실행 방법·구현 상태·설계 상세는 해당 프로젝트 문서를 원본으로 유지한다. 프로젝트 문서에서 예외를 안내할 때는 위키의 해당 항목을 링크한다. 작은 프로젝트는 별도 문서를 늘리지 않고 README에 적용 상태를 기록해도 된다.

프로젝트 제약이나 명시적 합의로 공통 기준과 달라질 때는 대상 규칙·적용 조건·이유·상태를 기록한다. 프로젝트의 기존 합의는 해당 범위의 예외로 관리하며 위키의 공통 기본값을 바꾸지 않는다. 위키에 아직 반영하지 못한 결정은 프로젝트에 임시 기록하고 후속 반영 대상으로 남긴다.

프로젝트 문서의 단일 파일·프로젝트별 폴더 구성과 분리 절차는 [프로젝트 문서의 확장과 분리](projects/index.md#프로젝트-문서의-확장과-분리)를 따른다.

### 마지막 확인·반영 시점

프로젝트에 위키의 확인일과 마지막으로 확인·반영한 커밋을 기록하는 것을 **권장**한다. 커밋 번호는 과거 규칙에 고정하기 위한 기준이 아니라 반영 상태를 추적하는 기록이다. 확인만 한 변경과 실제 코드에 반영한 변경은 구분한다. 미커밋 초안을 사용했다면 문서·변경 내용·시험 적용 대상을 기록한다.

예를 들어 프로젝트에서 처음 정한 오류 처리 방식은 우선 시험 적용으로 기록한다. 공통으로 사용할 수 있는 부분은 위키의 오류 처리 초안에, Win32 전용 처리는 프로젝트별 문서에 반영한다. 사용자가 공통안을 채택하면 위키의 상태를 갱신하고 프로젝트에 적용 결과를 기록한다.

위키 문서 편집과 커밋·푸시·배포는 별개다. 이 절차가 원격 반영이나 무관한 코드의 일괄 수정을 자동 승인하지 않는다.

## 변경 기록

- 2026-10-06: 자료형 선택·변환 초안을 작성하고 [자료형 선택과 별칭](coding/cpp/type-selection.md)과 [타입 변환과 범위 검사](coding/cpp/conversions.md)로 분리했다. 자체 별칭 도입·강한 타입·목적별 캐스트·숫자 범위를 정리하고 [RnimanEngine](projects/rniman-engine.md#자료형과-변환-초안의-확인-상태)에 확인 범위와 미적용 대상을 기록했다. 목차·초기화 링크·사이트 메뉴를 갱신하고 C++ 탐색 순서를 코드 표현, 값과 타입, 파일·API·자원 관리 순으로 맞췄다. 각 문서의 동일 날짜 변경 기록을 하나로 통합했다. 각 문서 상단은 상위 목차 링크만 남기고 관련 링크는 하단의 관련 문서 목록으로 옮겨 도입부를 간결하게 했다. 링크 제목과 초안 표시도 통일했다. 상태·적용 범위·버전 안내는 사이트에서 본문보다 작은 글씨와 보조 색상·여백으로 구분했다. 사용자 요청에 따라 사이트 제목·본문·메뉴에 Pretendard Variable v1.3.9를 적용하고 글꼴·라이선스를 저장소에 포함했으며 코드의 고정폭 글꼴은 유지했다. 공식 원본과의 일치 및 SIL OFL 1.1 배포 조건을 확인하고 출처·해시·저작권 고지를 기록했다. 두 문서는 초안을 유지하며 기존 채택 규칙과 프로젝트 코드는 변경하지 않았다.

- 2026-10-05: [RnimanEngine 카메라 입력과 여러 Transform](projects/rniman-engine.md#카메라-입력과-여러-transform의-시험-적용)의 입력 초기화·Transform·WVP 목록 수명·오브젝트별 상수 영역과 [겹침 픽셀 검증](projects/rniman-engine.md#겹침-픽셀-검증의-시험-적용)의 테스트 전용 readback·Present 생략·픽셀 비교를 프로젝트 한정 시험 적용으로 기록했다. 공통 채택 규칙은 유지했다.
