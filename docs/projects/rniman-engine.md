## 컨벤션 적용 상태

공통 기준은 [위키의 채택 규칙](../baseline.md)이다. 프로젝트의 새 결정은 [상호 반영 절차](../baseline.md#위키와-프로젝트의-상호-반영)에 따라 위키에 반영한다.

최초 원격 조사에서는 과거 커밋 고정 안내를 확인했다. 이후 로컬 엔진 커밋 73f1cc0의 위키 중심 절차와 이번 D3D12 구현 작업 트리를 확인했다. 이 문서의 새 선택과 엔진 구현은 로컬에 반영했으며 원격 최신 상태·푸시·배포 완료는 확인하지 않았다.

## 프로젝트 제약과 전용 기준

아래는 조사 시점에 확인한 선택의 요약이다. 공통 규칙의 자동 채택을 뜻하지 않으며 설정 상세는 원본 개발 문서를 따른다.

| 항목 | 상태·핵심 내용 | 공통 기준과의 관계 |
| --- | --- | --- |
| 대상 환경 | Windows·C++20·MSVC, x64 | 다른 플랫폼이나 언어 버전의 공통 요구로 확대하지 않음 |
| PCH | 구현 파일에서 PCH 선행 사용 | [헤더 규칙](../coding/cpp/headers.md)의 허용 범위이며 헤더 독립성·직접 include는 유지 |
| 출력 구분 | 프로젝트·빌드 구성별 출력 분리 | 다중 플랫폼 추가 시 충돌 조건을 재검토. 구체적인 경로는 원본 구조 문서에서 관리 |
| 텍스트 설정 | Windows 명령 스크립트의 CRLF | C++ 소스의 [UTF-8·LF 기준](../coding/cpp/formatting.md)을 변경하지 않음 |
| 자원 수명 | GPU 사용 완료까지 자원 재사용·해제를 미룸 | 아래 초기 구현 선택과 프레임 동기화 전환으로 구체화 |

오류 처리·ECS 저장 방식·Unity 데이터 규격 등 미결정 사항은 원본 설계 문서에서 구체화한다. 실제 결정 중 공통화할 내용은 해당 위키 주제로, 프로젝트 고유 규칙은 이 문서로 반영한다.

## D3D12 초기 구현 선택

2026-09-15 사용자 선택에 따라 **Sandbox 초기 D3D12 구현 범위에서 채택**한다. 공통 C++ 규칙이나 다른 프로젝트로 확대하지 않는다.

| 선택 | 적용 조건·이유 |
| --- | --- |
| 앱이 창과 렌더러를 각각 소유 | 창의 메시지 처리와 GPU 수명을 분리. 렌더러를 창보다 먼저 정리 |
| 고성능 하드웨어 GPU 우선, 미지원 시 오류 | 하드웨어 선택 결과를 명확히 유지. WARP 자동 대체 없음 |
| 매 프레임 Fence 대기(초기 구현 당시) | 초기 수명 검증을 단순화하기 위한 선택. 2026-09-17 아래 프레임 동기화 전환으로 대체 |
| WM_SIZE는 크기를 기록, 프레임 경계에서 리사이즈 | 창 콜백과 GPU 자원 재생성을 분리. 최소화·0 크기에는 렌더링 중지 |

구현 단계의 **시험 적용**은 ComPtr·렌더러 소유 Event, bool 실패 반환과 API/HRESULT 보고, Debug 레이어 필수, VSync·두 백 버퍼다. 소유권을 명확히 하고 초기 진단 경로를 연결하기 위한 최소 선택이며 통일 오류 정책·다중 프레임 설계의 채택을 뜻하지 않는다. 시험 적용 결과와 제한은 [원본 검증 기록](https://github.com/rniman/RnimanEngine/blob/main/docs/development.md#d3d12-화면-출력과-검증)에 둔다. 새 절은 로컬 수정이 원격에 반영된 뒤 접근할 수 있다.

일반화 후보는 HRESULT 실패 정보와 GPU 자원 수명이다. 현재는 Sandbox 한 곳의 적용 사례이므로 공통 규칙으로 올리지 않는다. 다른 실제 사용 경로에서 요구가 확인되면 공통 오류 처리·소유권 규칙과의 경계를 다시 검토한다.

## 프레임 동기화 전환

2026-09-17 사용자 요청으로 **Sandbox의 프레임별 Command Allocator·Fence 값과 재사용 시 대기를 프로젝트 한정 채택**했다. 리사이즈·종료에는 전체 GPU 완료 대기를 유지한다. 이전 화면 검증 선행 조건은 이번 요청 범위에서 변경했으며 남은 미검증 항목을 완료로 간주하지 않는다.

현재 두 백 버퍼에 대응하는 슬롯, 단일 Command List와 공유 Fence/Event는 Sandbox에 한정한 구현 선택이다. Allocator는 해당 제출의 완료 후에만 재사용하며 제출 실패 시에도 자원 정리를 시도한다. 이 선택을 다중 Queue나 공통 C++ 동기화 규칙으로 확대하지 않는다. 상세 흐름·검증 결과·성능 미측정 상태는 [원본 개발 문서](https://github.com/rniman/RnimanEngine/blob/main/docs/development.md#프레임별-fence-동기화)에서 관리한다.

## 코드 가독성 적용

2026-09-15 Sandbox·RendererSmoke 코드에 [작업 경계와 인자 배치](../coding/cpp/formatting.md#작업-경계와-빈-줄)를 적용했다. 기존 소유권·GPU 동기화와 식별자를 유지하며 작업별 실패 처리와 빈 줄을 정리했다.

**적용 경과:** 위 코드 정리 당시에는 120열을 시험 적용했다. 이후 2026-09-15 사용자 선택으로 [긴 줄과 함수 인자](../coding/cpp/formatting.md#긴-줄과-함수-인자)의 공통 기준이 개정되었다. 앞으로의 배치는 해당 채택 규칙을 따른다. 이번 위키 개정에 따른 엔진 코드·도구 설정의 추가 반영 여부는 확인하지 않았다.

## 공통 초안의 근거

- [검증 결과 기록](../quality/verification.md): 빌드·실행·시각 확인을 구분한 사례는 원본 개발 문서를 참조한다. 검증 로그는 위키에 복제하지 않는다.
- [원본과 생성물 관리](../git/artifacts.md): 기준 에셋과 재생성 결과를 구분한 사례는 원본 구조 문서를 참조한다. 파일별 추적 정책과 변환 계획은 프로젝트에서 관리한다.

두 공통 문서는 아직 초안이다. 과거 개인 자료는 비교 근거이며 이미 채택된 위키 규칙이나 현재 프로젝트의 미결정 상태를 대체하지 않는다.
